<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted localStorage -> runtime state | untrusted stale or malformed local data is consumed on startup |
| sanitized store output -> controller rehydration | invalid assumptions here can break puzzle launch or corrupt progress |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | T (Tampering) | `solvedIds` / `activeState.puzzleId` in localStorage | mitigate | Validate persisted IDs against bundled catalogue and drop stale/invalid entries before controller uses them |
| T-08-05 | D (Denial of Service) | controller startup rehydration path | mitigate | Preserve try/catch fallback to fresh parsed puzzle board when persisted board/undo snapshots are malformed |
| T-08-06 | R (Repudiation) | progress migration behavior | accept | Deterministic sanitization rules are test-encoded; explicit audit logging not required for local-only non-account scope |
</threat_model>
