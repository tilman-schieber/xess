<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted local state -> runtime navigation | `activeState` and `solvedIds` from localStorage influence resume routing |
| UI events -> screen state transitions | user pointer/keyboard actions drive mode changes (`start`, `tracks`, `play`) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | T (Tampering) | localStorage-derived resume routing | mitigate | Validate active puzzle ID against selected track before using; fallback to deterministic in-track ID |
| T-07-08 | D (Denial of Service) | `mountGameUi` screen-state transitions | mitigate | Guard unknown screen states and unknown track IDs to safe default (`tracks` screen) |
| T-07-09 | I (Information Disclosure) | DOM rendering in start/track screens | mitigate | Keep text rendering on `textContent`; avoid user-controlled HTML insertion in new screen paths |
</threat_model>
