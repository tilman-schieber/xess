<objective>
Fix the board layout so cells are always square and the board's aspect ratio matches the puzzle grid dimensions (width:height). A 4×3 grid produces a 4:3 board; a 5×5 grid produces a square.

Purpose: Currently the board forces `aspect-ratio: 1/1` regardless of grid shape, causing non-square puzzles to stretch cells vertically or horizontally. The fix sets `--rows` as a CSS custom property and lets the grid drive board height from the row count.

Output: Updated `board.css` and `main.js` — no new files.
</objective>

  <name>Task 1: Update board.css — remove forced aspect-ratio, add per-cell square sizing, add --rows grid rows</name>
  <files>src/styles/board.css</files>
  <action>
Make exactly these three targeted changes to src/styles/board.css:

1. In the `.board` rule:
   - REMOVE the line: `aspect-ratio: 1 / 1;`
   - REPLACE the line `grid-auto-rows: 1fr;` with:
     `grid-template-rows: repeat(var(--rows), 1fr);`

   Rationale: `aspect-ratio: 1/1` on the board overrides natural height; removing it lets
   the grid rows drive the board height. `grid-template-rows` with `--rows` gives explicit
   row sizing controlled by the puzzle dimensions.

2. In the `.cell` rule:
   - ADD `aspect-ratio: 1 / 1;` as a new property (any position within the rule is fine).

   Rationale: All cells — including void cells — must occupy square slots in the grid.
   Void cells are `visibility: hidden` so they are invisible; adding aspect-ratio to them
   is harmless and ensures uniform grid track sizing.

3. In the `.cell--playable` rule:
   - REMOVE the line `aspect-ratio: 1 / 1;` (it is now inherited from `.cell`).

   Rationale: De-duplicate; `.cell` already carries the rule.

No other changes to board.css. All other rules, comments, media queries, and custom
properties remain exactly as they are.
  </action>
