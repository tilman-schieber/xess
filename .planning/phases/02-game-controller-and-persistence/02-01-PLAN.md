Board is Map<"col,row", Cell> where Cell = { piece: Piece|null, isGoal: boolean }
Piece = { type: string, color: string, direction?: [number, number] }

Puzzle runtime object fields relevant to persistence:
  id: string          — stable opaque ID (FMT-04), used as key discriminator
  goalType: string    — 'capture-all-targets' | 'reach-all-goal-squares'
  targetColor: string|null

Active puzzle state to persist:
  puzzleId: string
  board: Map<string, Cell>   — MUST serialize/deserialize as [entries] array (Map is not JSON-native)
  undoStack: Map<string, Cell>[]   — array of board snapshots (ENG-08 caller-owned stack)

IMPORTANT: Map serialization — JSON.stringify(map) silently produces "{}".
Use Array.from(map.entries()) to serialize, new Map(entries) to deserialize.
structuredClone is NOT available in localStorage context — use JSON round-trip with Map<->entries conversion.

<feature>
  <name>localStorage Persistence Layer</name>
  <files>src/store/store.js, src/store/store.test.js</files>
  <behavior>
    Storage schema (STORAGE_KEY = 'xess_v1'):
    {
      schemaVersion: 1,
      solvedIds: string[],         -- PRS-01: IDs of all solved puzzles
      activeState: {               -- PRS-02: last-played puzzle in-progress
        puzzleId: string,
        boardEntries: [string, Cell][],   -- serialized Map entries
        undoEntries: [string, Cell][][]   -- serialized array of board snapshots
      } | null
    }

    Behavior cases (write as Vitest tests FIRST — RED gate before implementation):

    loadStore():
    - Returns default { schemaVersion: 1, solvedIds: [], activeState: null } when localStorage is empty
    - Parses and returns stored data when STORAGE_KEY exists and schemaVersion matches
    - Returns default (wiping old data) when stored schemaVersion !== CURRENT_SCHEMA_VERSION (PRS-03)
    - Handles JSON.parse errors (corrupted data) by returning default

    saveProgress(solvedIds):
    - Merges updated solvedIds into existing store and writes back to localStorage
    - Deduplicated: passing the same id twice does not create duplicate entries

    saveActiveState(puzzleId, board, undoStack):
    - Serializes board Map via Array.from(board.entries()) into boardEntries
    - Serializes each undoStack board snapshot the same way into undoEntries
    - Writes activeState into store; loadStore() re-hydrates Map objects correctly

    clearActiveState():
    - Sets activeState to null in localStorage

    flushSync():
    - Writes the in-memory pending write (if any) to localStorage immediately (used on visibilitychange:hidden)
    - When nothing is pending, flushSync() is a no-op

    Debounce behavior:
    - saveActiveState called multiple times rapidly triggers only ONE localStorage write after DEBOUNCE_MS (300ms)
    - flushSync() cancels the pending debounce timer and writes immediately
    - After flushSync, a subsequent saveActiveState restarts the debounce

    visibilitychange registration:
    - store.js registers document.addEventListener('visibilitychange', ...) on module load
    - When document.visibilityState === 'hidden', flushSync() is called (PRS-04)
    - Registration must be idempotent: importing store.js multiple times must not double-register
  </behavior>
  <implementation>
    After all tests are RED:

    1. Define STORAGE_KEY = 'xess_v1' and CURRENT_SCHEMA_VERSION = 1 and DEBOUNCE_MS = 300 as module-level constants.

    2. Implement loadStore() — reads localStorage.getItem(STORAGE_KEY), JSON.parse, schema version guard, try/catch for parse errors.

    3. Implement _write(patch) — internal function: reads current store via loadStore(), merges patch, JSON.stringify, localStorage.setItem.

    4. Implement saveProgress(solvedIds) — calls _write({ solvedIds: [...new Set(solvedIds)] }).

    5. Implement saveActiveState(puzzleId, board, undoStack):
       - Serialize board: Array.from(board.entries())
       - Serialize undoStack: undoStack.map(b => Array.from(b.entries()))
       - Store pendingWrite = { puzzleId, boardEntries, undoEntries }
       - Debounce: clearTimeout(debounceTimer); debounceTimer = setTimeout(() => _writeActive(pendingWrite), DEBOUNCE_MS)

    6. Implement _writeActive(state) — calls _write({ activeState: state }).

    7. Implement flushSync() — if debounceTimer is set: clearTimeout(debounceTimer); debounceTimer = null; if pendingWrite: _writeActive(pendingWrite); pendingWrite = null.

    8. Implement clearActiveState() — flushSync() first, then _write({ activeState: null }).

    9. visibilitychange listener — register once at module load:
       if (typeof document !== 'undefined') {
         document.addEventListener('visibilitychange', () => {
           if (document.visibilityState === 'hidden') flushSync()
         })
       }
       The typeof document guard prevents crashes in the Vitest node environment.

    Export named: { loadStore, saveProgress, saveActiveState, clearActiveState, flushSync }
  </implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage read | Data written by a previous session; may be stale, malformed, or manually edited |
| visibilitychange | Browser fires this; no untrusted input, but timing is non-deterministic |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | loadStore JSON parse | mitigate | try/catch around JSON.parse; malformed data returns default (not crash) |
| T-02-02 | Tampering | schemaVersion mismatch | mitigate | strict equality check: parsed.schemaVersion !== CURRENT_SCHEMA_VERSION returns default and overwrites |
| T-02-03 | Denial of Service | localStorage quota exceeded | accept | QuotaExceededError on setItem is an unrecoverable edge case at puzzle-scale data (~5KB); log to console and swallow |
| T-02-04 | Information Disclosure | localStorage readable by same-origin JS | accept | no sensitive data; puzzle progress is non-confidential |
</threat_model>
